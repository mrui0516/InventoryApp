# Finance and Expenses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin-only Finance section: record expenses and supplier payments, split purchases between the shops, and show monthly net profit, spend by category, and cash in and out.

**Architecture:** New models in `stock/models/expenses.py`; all figures in `stock/services/finance.py`, one function per block; views in a new `stock/finance_views.py`. Debts between shops stay derived: `store_stock.balances()` adds each shop's share of supplier payments, and shops settle with the existing `StoreSettlement`.

**Tech Stack:** Django 5.2, SQLite, server-rendered templates, Bootstrap, the Orders row-and-panel pattern.

**Spec:** `docs/superpowers/specs/2026-11-04-expenses-design.md`

## Global Constraints

- Every Finance view and API uses `@login_required` + `@admin_required`; nav links show for `user.is_superuser` only.
- `Expense.period` is always the 1st of the month. `paid_on` empty means unpaid. `method` is `cash` or `bank`, required when `paid_on` is set.
- Net profit = gross profit (all categories, all channels) + `SaleOrderCharge` collected − expenses by `period`. Supplier payments never touch net profit.
- Cash flow uses actual dates. `cash` tender = Cash; `card`, `mbway` = Bank. `ARPayment` `cash` = Cash, others = Bank. `StoreSettlement` = Cash, hidden in the all-shops view.
- Debts from purchases are never stored as rows; they are computed from `SupplierPayment` and the order's batches.
- Orders with `created_at` before `BusinessSettings.payables_from` never count as owing.
- UI text in English; no intro paragraphs; fonts >= .85rem; `minmax(0,1fr)` grids; screenshots on phone (390) and desktop (1366) before calling a page done.
- Each task updates `docs/PRD.md`, `docs/ARCHITECTURE.md` and `docs/STATUS.md`.
- Run tests: `python manage.py test stock restock_alerts` on a `git archive HEAD` export with `.env` copied in.

## Review Focus

- An order whose lines all cost 0: `purchase_shares` must not divide by zero; it owes nothing between shops.
- Shares that do not divide evenly: €100 split three ways must add back to exactly €100.
- Rolling back a receipt after a payment: the debt falls back to the pending allocation, and to nothing where there is none.
- Double-tapping Confirm on a due expense: one `Expense` only.
- An expense paid in a different month from its `period`: it counts in that period's profit and in the payment month's cash flow.
