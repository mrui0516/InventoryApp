# 财务支出系统 设计文档

日期：2026-11-04　状态：已确认

## 1. 为什么做

系统现在知道卖了多少、毛利多少，但完全不知道钱花到了哪里：没有支出记录，没有工资，也不知道欠供应商多少。所以老板看不到真正赚了多少，也看不到钱什么时候出去。

要回答三个问题：

1. 这个月每家店、公司合计**真正赚了多少**（净利润）？
2. 钱**花在哪些类别**上，和上个月比怎样？
3. 这个月**实际进出多少钱**，还有哪些**该付没付**？
4. 老板**自己投入了多少钱**，取回多少，生意现在**值多少**？

## 2. 目标与边界

**目标**

- 记录四类支出：固定月费、员工工资、进货付款、零散支出。
- 每月看到：按店和合计的净利润、按类别的花费、现金流和应付。

**不做**

- 不做正式会计：没有复式记账、资产负债表，也不算增值税（IVA）。金额按实际付出的数字记。
- 不做给会计的报表和票据附件（这次没选，以后可以加）。
- 不做工资计算：不按考勤算工资，也不算社保，只记实际发了多少。
- 不做费用分摊：两家共同的费用，由老板自己拆成两笔录入。

**做错了算失败**

- 净利润算重：进货款既进了毛利的成本，又被扣一次。
- 员工或经理能看到工资和净利润。
- 上线后现有几百张进货单全部显示成"欠款"，页面没法用。

## 4. 数据模型（迁移 0072）

放在新文件 `stock/models/expenses.py`。

**`ExpenseCategory`**：`name`（唯一）、`is_active`、`sort_order`。迁移时预置：Rent、Utilities、Salaries、Marketing、Packaging、Shipping、Accounting、Software、Maintenance、Other。管理员可增加、停用；用过的类别不能删，只能停用。

**`Expense`**：一笔费用。

| 字段 | 说明 |
|---|---|
| `store` | FK，必填，PROTECT |
| `category` | FK，必填，PROTECT |
| `amount` | Decimal，> 0 |
| `period` | 日期，固定存当月 1 号：**这笔费用算哪个月的利润** |
| `paid_on` | 日期，可空：**钱实际哪天出去**；空 = 还没付，算应付 |
| `method` | `cash` / `bank` / `owner`（老板自己的钱），`paid_on` 有值时必填 |
| `payee` | 文本：付给谁（房东、员工姓名等） |
| `note` | 文本，可空 |
| `template` | FK 到 `ExpenseTemplate`，可空，SET_NULL |
| `created_by`、`created_at`、`updated_at` | |

`period` 和 `paid_on` 分开，是因为 10 月的房租可能 11 月 2 日才付：利润算 10 月，现金流算 11 月。

**工资没有单独的表**：就是类别为 Salaries 的 `Expense`，`payee` 写员工姓名，每位员工一个模板。不是所有员工都有系统账号，所以不关联 User。

**`ExpenseTemplate`**：固定月费和工资的模板。`store`、`category`、`amount`、`payee`、`note`、`is_active`。

**`SupplierPayment`**：一笔给供应商的付款。

| 字段 | 说明 |
|---|---|
| `inbound_order` | FK，必填，PROTECT |
| `store` | FK，必填，PROTECT：钱从哪家店出，默认 `BusinessSettings.purchasing_store`（Scentory），可以改 |
| `amount` | Decimal，> 0 |
| `share_markup` | Decimal，默认 0：付款时的每件加价，从设置复制过来，以后改设置不影响这笔 |
| `paid_on`、`method`（cash / bank / owner）、`note`、`created_by`、`created_at` | |

**`OwnerFunding`**：老板投入或取出的钱。`store`（FK，必填，PROTECT）、`kind`（`in` 投入 / `out` 取出）、`amount`（> 0）、`date`、`method`（`cash` / `bank`）、`note`、`created_by`、`created_at`。以前投入的钱，可以按当时日期补录。

**`BusinessSettings.payables_from`**：日期，迁移时设为上线当天。

**`BusinessSettings.purchasing_store`**：FK 到 Store，迁移时设为 Scentory，在 Shop settings 里可改。

**`BusinessSettings.purchase_share_markup`**：Decimal，默认 0.00，在 Shop settings 里设置（Purchase share markup，€ / 件）。和调货加价（`transfer_markup`）是两个独立的设置。

## 5. 计算

全部放在新文件 `stock/services/finance.py`，一个函数对应一块数字，不写在视图里。

**月度利润**（某店或合计，只看 `period` 在这个月的费用，不管付没付）：

```
毛利（所有分类、所有渠道，已扣刷卡手续费；单店时含调货加价）
+ 向客人收的运费杂费（SaleOrderCharge）
− 各类别费用
= 净利润
```

- 毛利直接用 `compute_period_headline(start, end, [], True, store)`，不要读看板的快照：看板默认只筛香水，数字不全。
- 运费杂费现在不算销售额，也不在毛利里。如果运费支出记成费用而收入不算，净利润会偏低，所以单列一行加回来。
- 合计用 `store=None` 算毛利（含没有店铺的旧销售），再减所有店的费用；调货加价两边抵消，新数据下合计等于各店之和。

**现金流**（只看实际日期在这个月的钱）：

| 进 | 现金 / 银行 |
|---|---|
| 销售收款（`SaleOrderPayment`，旧订单用行上的付款方式） | cash 算现金；card、mbway 算银行 |
| 刷卡手续费 | 从银行扣（`SaleOrder.card_fee`） |
| IOU 收款（`ARPayment`） | cash 算现金；其余算银行 |
| 收到另一家店的结账（`StoreSettlement`，单店时） | 按付款方式：这张表没有方式，一律算现金 |

| 出 | |
|---|---|
| 已付费用（`Expense.paid_on`） | 按 `method` |
| 供应商付款（`SupplierPayment.paid_on`） | 按 `method` |
| 付给另一家店的结账（单店时） | 算现金 |

老板资金：`OwnerFunding` 的投入算进、取出算出，按 `method` 进现金或银行。`method=owner` 的支出和进货款**不进现金和银行**，因为钱没从店里出去；单独显示一行"老板代付"。

结果显示：现金、银行各自的进、出、净额，以及合计。不显示账户余额（老板决定先只看每月进出）。

- 合计视图里，两店之间的结账不显示：一进一出抵消。
- IOU（`ARInvoice`）是独立的欠款记录，不是 `Sale`，所以 IOU 只进现金流，不进利润。

**应付**：

- 未付费用：`paid_on` 为空的 `Expense`。
- 欠供应商：`created_at >= payables_from` 的进货单，应付 − 已付 > 0。
  - 应付：已收货按批次的 数量 × 成本 求和；待收货按待收货明细求和（你说过常常先付款后到货，所以待收货的单子也要能付款）。
  - 上线前的进货单不算欠款，这样不会出现"几百张单全显示欠款"。
  - 超付时显示负数（表示供应商欠你），不拦截：多付、预付都可能发生。

**进货款的分配**（`purchase_shares()`）：不写单独的账，每次从付款和收货现算，所以收货、改单、撤销收货、删付款之后都会自动跟着变。

- 一笔付款按这张进货单**各店收到的成本比例**分配：已收货按批次的 `received_store`（数量 × 成本，调货不影响）；待收货按待收货明细里已填的分配。
- 还没分配的待收货单：先不产生欠款，收货分配后自动算出来。
- 付款的店之外，每家店欠付款店它的那部分，例如 Scentory 付 €1000，Khan 收了 60% 的货，Khan 欠 Scentory €600。部分付款按同样比例。
- 这部分并入 `balances()`，和调货欠款一起抵消，Transfers 页顶部显示净额；Khan 付钱时用现有的 Settle 记 `StoreSettlement`。余额下面写明构成：调货、进货分配、已结账。
- 只影响两店之间的欠款和现金流，**不影响公司利润**：批次成本不变，卖出时哪家店卖就算哪家店的成本。
- **加价（默认 0，保留功能）**：`share_markup` 大于 0 时，欠款 = 成本部分 + 加价 × 这部分的件数（部分付款按比例）。加价按调货加价的方式进单店利润：付款日当月，付款店 +、分担店 −，公司合计抵消（并入 `transfer_margins` 或在 `finance` 里同样处理）。

例子（Khan 收 60%）：Scentory 现金流出 €1000；Khan 结账时 Khan 出 €600、Scentory 进 €600；公司合计只出 €1000。

**老板资金**（累计到所选月份月底）：

```
投入 = OwnerFunding(in) + method=owner 的已付支出 + method=owner 的进货款
取出 = OwnerFunding(out)
净投入 = 投入 − 取出
```

**生意现值**（现在这一刻，不跟月份走）：库存成本（所有批次 remaining × cost）+ IOU 应收（未结清的 `ARInvoice`）− 欠供应商 − 未付费用。不含手上的现金和银行存款，页面上注明。

**累计净利润**：从 `payables_from` 起到所选月份的净利润之和，和净投入放在一起看。上线前没有支出记录，所以不往前算。

老板资金和现值都是**公司层面**：选单店时只显示这家店的投入和这家店的库存、应收，欠供应商按付款店不好归属，只在全部店铺时显示现值。

## 6. 页面

侧栏新增一组 **Finance**（只有管理员看得到），在 Settings 之上。三页都跟随左上角的店铺选择，"全部店铺"显示合计；**新增支出**必须选店，默认当前店。所有页面都要在手机上可用。

**Finance（总览）** `/finance/`：顶部月份切换（沿用看板的 ‹ 月份 ›）。

- 数字格：净利润、毛利、费用合计、现金净流入、应付合计；净利润和费用带"比上月"。
- 利润表：一行一项，和第 5 节的算式一致；全部店铺时增加每店一列。
- 按类别：今月、上月、差额。点类别进入 Expenses 并筛到这个类别。
- 现金流：现金、银行两列的进和出。
- 本月待确认：见下。

**Expenses** `/finance/expenses/`：沿用 Orders 的列表样式（紧凑行，手机两行，点开侧边面板）。

- 筛选：月份、类别、已付 / 未付。
- 顶部 **+ Add expense**：店、类别、金额、月份（默认本月）、已付（默认勾选，日期默认今天，方式默认上次用的）、付给谁、备注。
- 面板里可以编辑、删除（先确认）、标记已付。

**固定月费**（Expenses 页的一个标签）：模板列表，可增删改、停用。

**待确认的逻辑**：不用定时任务。打开 Finance 时，对每个启用的模板，如果这个月还没有它的 `Expense`（同模板、同 `period`），就显示一行"待确认"，金额可改，点 **Confirm** 才生成 `Expense`；**Skip** 把这个模板这个月略过。切到过去的月份同样显示，这样漏记的能补。

- 需要记录"略过"：`ExpenseTemplateSkip(template, period)`，唯一。
- 改模板金额不影响已生成的 `Expense`。

**Owner funds** `/finance/owner/`：投入和取出的记录，可增删改；顶部显示累计投入、取出、净投入。Finance 总览增加一块"老板资金与现值"：净投入、累计净利润、生意现值及其构成。

**Suppliers 欠款** `/finance/payables/`：

- 按供应商汇总欠款，点开列出未付清的进货单：单号、发票号、应付、已付、还欠。
- 每张单有 **Pay**：金额（默认还欠的数）、日期、方式、从哪家店出（默认 Scentory）。
- 已付的单子显示分配结果，例如 "Khan €600 · Scentory €400"。
- 付款记录可以删除（先确认）。

**现有页面的改动**

- Orders → Purchases 的记录面板：管理员能看到已付、还欠。经理不显示。
- Transfers 页的余额包含进货分配（经理本来就能看这一页和成本）；具体付款记录只有管理员能看。
- Purchases 的 Paid 模式仍按下单日期，不改成实际付款日。
- **"Net Profit" 改名**：Today 和客户页现在把"毛利减刷卡手续费"叫 Net Profit，和新的净利润冲突。改成 **Profit**。
- 取消待收货单、删除进货单时，如果已有付款，拒绝并提示先删除付款。撤销收货（Roll back）不受影响，付款留在单子上。

## 7. 权限与审计

- 所有 Finance 页面和接口用 `admin_required`，导航也按 `is_superuser` 隐藏。
- 看板、Today、员工页都不显示费用和净利润。
- 新增、修改、删除都写进 Audit（新增一个 Audit 页 **Finance**，记录谁、什么时候、改前改后的金额）。

## 8. 开发顺序

每步都能单独上线：

1. 模型、类别、Expenses 列表和新增。
2. 固定月费模板和待确认。
3. 供应商付款和欠款页，包括 `payables_from`、进货分配并入两店余额。
4. Finance 总览（利润、类别、现金流）。
5. 老板资金和生意现值。
6. 改名、Purchases 面板、Audit。

每步都要有测试，重点测：净利润不含进货付款；进货加价默认 0、改设置不影响已有付款；两店合计等于各店之和；进货分配按收货成本比例，调货不改变它，和调货欠款正确抵消；上线前的进货单不算欠款；经理和员工访问全部被拒绝。
